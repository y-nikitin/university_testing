# SUT C — Інтерфейс бронювання готелю

HTML, CSS та JavaScript. Використовує реальний REST API сусіднього проєкту sut-b-hotel-java та його PostgreSQL.

## Запуск

Підготуйте БД і застосуйте міграції за інструкцією SUT B. Задайте його DB_URL, DB_USER та DB_PASSWORD.
У PowerShell із папки sut-b-hotel-java запустіть:

```powershell
mvn spring-boot:run
```

Або запустіть BookingApi кнопкою в IDE. Робоча папка запуску має бути sut-b-hotel-java: від неї визначається шлях до сусідньої sut-c-ui.

Відкрийте http://127.0.0.1:8080/index.html. Якщо API_PORT змінено, використайте відповідний порт.
UI та API працюють на одній адресі. Не відкривайте index.html як локальний файл.
Окремої збірки frontend не потрібно. Дані залишаються в БД після зупинки.

## Можливості

- Створити номер або знайти його за ID.
- Обрати номер та оформити бронювання.
- Знайти бронювання за ID; адреса з параметром booking дозволяє відкрити його повторно після перезавантаження.
- Побачити збережені суму, кількість гостей, ночей та статус.
- Скасувати бронювання та побачити зміну статусу.
- Повторити скасування й отримати повідомлення про бізнес-відмову.

Ціна номера вводиться у гривнях, API отримує копійки. Знижку обчислює виключно backend: від 7 ночей — 5%. Наприклад, при ціні 1000 грн за ніч 6 ночей коштують 6000 грн, а 7 — 6650 грн.

Перевищення місткості номера викликає бізнес-відмову. Форми мають базові обмеження обов’язкових і числових полів. Помилки сервера показуються в області role=alert; результат операції — role=status.

## Автоматизація

Використовуйте назви кнопок, підписи полів або data-testid. Для збережених значень доступні booking-id, booking-status і booking-total; сума в копійках — data-kopecks, статус API — data-status.
Очікуйте видимий результат завершення операції. Кожен сценарій має створювати власні дані з унікальними кодами.
Готових UI-тестів немає.

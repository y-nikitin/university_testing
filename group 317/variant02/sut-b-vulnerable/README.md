# SUT B — Навчальна вразлива версія, варіант 02

Лише локальне security testing з вигаданими даними. Звичайні SUT B і C не змінено.
Основна поведінка відповідає сусідньому sut-b; ця копія навмисно порушує частину вимог.

## Персональне правило

Передоплата — 30% суми проживання, для постійного клієнта — 10%. Знижок немає. Скасування повертає всю передоплату.

## Запуск

Python 3.12+, PostgreSQL. Створіть окрему БД hotel317_variant02_security і користувача hotel_security.
Застосуйте SQL-файли migrations у порядку назви до порожньої БД.
Параметри: SECURITY_DB_HOST (localhost), SECURITY_DB_PORT (55433),
SECURITY_DB_NAME (hotel317_variant02_security), SECURITY_DB_USER (hotel_security), SECURITY_DB_PASSWORD.
Використовуйте окрему навчальну БД. Файл .env автоматично не читається.

Із папки sut-b-vulnerable, в окремому віртуальному середовищі:

```sh
python -m pip install -e .
python -m uvicorn hotel.api:app --host 127.0.0.1 --port 8082
```

UI: http://127.0.0.1:8082/index.html. Папка sut-c-vulnerable має бути сусідньою.
Запускайте варіанти по черзі або задавайте різні порти.

## Очікувані вимоги до додаткових операцій

GET /bookings/search?reference=... має шукати тільки точний код.
PATCH /bookings/{id} призначений тільки для зміни reference.
Суми total, prepaid, refund визначає Service; статус змінюється через бізнес-дії.
Клієнт не повинен мати можливості підмінити ці поля.
Відповіді про помилки не повинні розкривати SQL, структуру БД чи stack trace.

## Межі комплекту

Ця копія містить production-код, міграції та навмисні вразливості. Готовий regression suite зі звичайного SUT B сюди не копіювався. Наявні залежності або профілі тестового фреймворку не означають наявності тестів. Використовуйте окреме середовище залежностей і власні security-перевірки.

# SUT C — Бронювання готелю, варіант 02

Готовий UI на HTML, CSS та JavaScript для сусіднього SUT B.

## Запуск

Підготуйте середовище, PostgreSQL, міграції та змінні БД за README SUT B.
Із папки sut-b виконайте звичайну команду запуску:

```sh
python -m uvicorn hotel.api:app --host 127.0.0.1 --port 8080
```

Відкрийте http://127.0.0.1:8080/. Окремий frontend-сервер не потрібний.
UI підключається автоматично за розташуванням файлів. Збережіть сусідні папки sut-b і sut-c-ui.
Подвійний клік по index.html не замінює запуск backend.

## Персональне правило

Передоплата — 30%, для постійного клієнта — 10%. Знижок немає; при скасуванні повертається вся передоплата.

Форма передає дати проживання та ознаку постійного клієнта. При скасуванні кількість днів до заїзду вводиться вручну, як передбачено SUT B.
Сума, передоплата, повернення коштів і статус показуються з відповіді backend. Frontend не обчислює бізнес-правила.
Ціна номера вводиться у гривнях; API отримує копійки.

## Можливості

Створення і пошук номера, оформлення та пошук бронювання, скасування і повідомлення про відмови.
Параметр booking в адресі дозволяє повторно завантажити бронювання після оновлення сторінки.
Кнопка скасування залишається доступною, щоб показати відповідь на повторну заборонену дію.

Для автоматизації доступні підписи полів, назви кнопок, role=status, role=alert та data-testid.
Збережені суми мають data-kopecks, статус — data-status. Кожен сценарій має готувати власні дані.
Готових UI-тестів немає.

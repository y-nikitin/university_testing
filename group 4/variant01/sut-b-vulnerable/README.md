# SUT B — Навчальна вразлива версія магазину, варіант 01

Лише локальне security testing із вигаданими даними. Звичайні SUT не змінені.

## Персональне правило

До 5 одиниць включно. Знижка 17% від 1000 грн включно незалежно від преміальності. Повернення до 3 днів включно лише із закритим пакуванням; акційність не обмежує повернення.

## Запуск

Створіть окрему PostgreSQL БД store_variant01_security, користувача store_student і задайте пароль.
Застосуйте SQL-файли migrations за порядком до порожньої БД.
Змінні: SECURITY_DB_HOST (localhost), SECURITY_DB_PORT (55433), SECURITY_DB_NAME (store_variant01_security),
SECURITY_DB_USER (store_student), SECURITY_DB_PASSWORD. Файл .env автоматично не читається.
Із папки sut-b-vulnerable:

```sh
npm install
npm start
```

Для Python використовуйте окреме віртуальне середовище. UI: http://127.0.0.1:8082/index.html.
Папка sut-c-vulnerable має бути сусідньою. Варіанти запускайте по черзі або на різних портах.

## Очікувані вимоги

Поведінка основних операцій — як у сусіднього sut-b.
GET /orders/search?reference=... має знаходити лише точний код.
PATCH /orders/{id} призначений тільки для зміни reference.
total визначає Service, status змінюється тільки через бізнес-дії. Клієнт не повинен підміняти ці поля.
Помилки API не повинні розкривати SQL, структуру БД чи stack trace.

## Межі комплекту

Ця копія містить production-код, міграції та навмисні вразливості. Готовий regression suite зі звичайного SUT B сюди не копіювався. Наявні залежності або профілі тестового фреймворку не означають наявності тестів. Використовуйте окреме середовище залежностей і власні security-перевірки.

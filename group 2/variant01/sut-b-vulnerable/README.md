# SUT B — Навчальна вразлива версія доставки, варіант 01

Лише локальне security testing з вигаданими даними. Звичайні SUT не змінені.

## Персональне правило

Вагова складова: 10 грн до 1000 г, 30 грн для 1001–5000 г, 60 грн для 5001–30000 г. Тариф — 50 грн + вагова складова + 0,10 грн за кілометр.

## Запуск

Створіть окрему PostgreSQL БД delivery_variant01_security і користувача delivery_student, задайте пароль.
Застосуйте міграції за порядком до порожньої БД.
Параметри: SECURITY_DB_HOST (localhost), SECURITY_DB_PORT (55433), SECURITY_DB_NAME (delivery_variant01_security),
SECURITY_DB_USER (delivery_student), SECURITY_DB_PASSWORD. Файл .env автоматично не читається.
Із папки sut-b-vulnerable:

```sh
mvn spring-boot:run
```

Для Python використовуйте окреме віртуальне середовище.
UI: http://127.0.0.1:8082/index.html. Папка sut-c-vulnerable має бути сусідньою.
Варіанти запускайте по черзі або на різних портах.

## Очікувані вимоги

Основні операції — як у сусідньому sut-b.
GET /shipments/search?reference=... має шукати лише точний код.
PATCH /shipments/{id} призначений лише для зміни reference.
Суму та коригування визначає Service; статус змінюється через бізнес-дії.
Клієнт не повинен підміняти total, adjustment чи status.
Помилки не повинні розкривати SQL, структуру БД чи stack trace.

## Межі комплекту

Ця копія містить production-код, міграції та навмисні вразливості. Готовий regression suite зі звичайного SUT B сюди не копіювався. Наявні залежності або профілі тестового фреймворку не означають наявності тестів. Використовуйте окреме середовище залежностей і власні security-перевірки.

# Тестування та верифікація ПЗ

Навчальні системи під тестуванням (SUT) для курсу «Тестування та верифікація ПЗ». Кожен варіант — незалежний проєкт зі своєю специфікацією. Спільного застосунку та єдиної команди запуску всього репозиторію немає.

## Як знайти свій варіант

1. Відкрийте папку своєї підгрупи: `group 1`, `group 2`, `group 3`, `group 4` або `group 317`.
2. Оберіть `variantXX` за **порядковим номером у підгрупі, а не в академічній групі**.
3. Перейдіть до потрібного SUT і прочитайте його `README.md`.

Наприклад: `group 1/variant03/sut-b/README.md`.

Номери можуть повторюватися між підгрупами. Обмінюватися варіантами всередині підгрупи не дозволяється. Використовуйте мову, для якої підготовлено ваш проєкт: Java, Python, C# або JavaScript.

## Структура

```text
group 1/ … group 4/
  variantXX/
    sut-a/
      README.md
      … бізнес-код
    sut-b/
      README.md
      … код і конфігурація проєкту
      migrations/
      … початкові тести

group 317/
  variant01/ … variant03/
    sut-a/
    sut-b/
```

Групи 1 і 2 мають по 18 реалізованих SUT B, групи 3 і 4 — по 17, група 317 — 3. Папки `variant18` у групах 3 і 4 містять лише попередні матеріали й не мають готового SUT B.

## Два SUT у варіанті

| Система | Призначення | Що містить |
|---|---|---|
| **SUT A** | Чорна скринька, модульні тести, тестові двійники, покриття та мутаційне тестування | Специфікація й невелика реалізація бізнес-логіки |
| **SUT B** | Інтеграційне тестування, PostgreSQL, HTTP та Testcontainers | Сервіс, репозиторії, SQL-міграції, конфігурація запуску та HTTP-адаптер зовнішньої політики |

Це окремі системи. Вимоги SUT A не переносяться автоматично на SUT B. Джерело очікуваної поведінки — README саме тієї системи, яку ви тестуєте.

Для лабораторної №1 працюйте за специфікацією **без перегляду вихідного коду**. Аналіз коду дозволено починаючи з лабораторної №2. Очікувані результати тестів визначайте за вимогами, а не підлаштовуйте під фактичну реалізацію.

## Теми SUT B

| Підгрупа | Предметна область |
|---|---|
| `group 1` | Реєстрація на навчальні курси |
| `group 2` | Доставка посилок |
| `group 3` | Прокат обладнання |
| `group 4` | Інтернет-магазин |
| `group 317` | Бронювання готелю |

У межах підгрупи варіанти мають спільну основу та персональні бізнес-правила: знижки, допуски, доплати, повернення тощо. Точні умови й API наведено в README варіанта. Однакові номери в різних підгрупах не означають однакові правила SUT B. Теми SUT A описано окремо в їхніх README.

## Запуск і тести

Виконуйте команди з папки конкретного `sut-b`. Версії середовища, залежності, міграції та налаштування БД наведено в його README й конфігураційних файлах.

| Мова | Типові команди |
|---|---|
| Java | `mvn compile`, `mvn test` |
| Python | `python -m pip install -e ".[test]"`, `python -m pytest` |
| C# | `dotnet build`, `dotnet test tests/<назва>.Tests.csproj` |
| JavaScript | `npm install`, `npm test` |

Для локальних інтеграційних тестів підготуйте окрему тестову PostgreSQL, застосуйте SQL-міграції з `migrations` і задайте параметри підключення за інструкціями проєкту. Файл `.env` автоматично не читається. Початковий тест підключення не замінює власних бізнес-сценаріїв.

Для SUT A тестовий проєкт та інструменти налаштовуються окремо відповідно до мови. Покриття й мутаційне тестування не мають спільної готової конфігурації на рівні репозиторію.

## HTTP та контейнерні тести

SUT B містить HTTP-реалізацію зовнішньої перевірки. Її адресу й таймаут передають під час створення; контракт запиту та відповіді наведено в коді адаптера й README там, де додано відповідний розділ. У локальних тестах залежність також можна замінювати Stub/Mock.

Для контейнерних сценаріїв студент налаштовує PostgreSQL і WireMock через Testcontainers, автоматичні міграції та підключення за параметрами запущених контейнерів. Наявність HTTP-адаптера сама по собі не запускає контейнери.

Після бізнес-операції перевіряйте фактичний стан PostgreSQL і запити в журналі WireMock. Кожен тест повинен готувати власні дані й забезпечувати їх ізоляцію. Готових розв’язків бізнес-тестів і контейнерних сценаріїв у студентських SUT B немає.

# SUT B — Навчальна вразлива версія прокату, варіант 15

Лише локальне security testing із вигаданими даними. Звичайні SUT не змінено.

## Персональне правило

До 3 одиниць для звичайного клієнта або до 10 для преміального дозволено на весь загальний строк. Більша кількість дозволена лише до 7 днів.

## Запуск

Створіть окрему PostgreSQL БД rental_variant15_security і користувача rental_student, задайте пароль.
Застосуйте SQL-файли migrations за порядком до порожньої БД.
Параметри: SECURITY_DB_HOST (localhost), SECURITY_DB_PORT (55433), SECURITY_DB_NAME (rental_variant15_security),
SECURITY_DB_USER (rental_student), SECURITY_DB_PASSWORD. Файл .env автоматично не читається.
Із папки sut-b-vulnerable:

```sh
mvn spring-boot:run
```

Для Python використовуйте окреме віртуальне середовище. UI: http://127.0.0.1:8082/index.html.
Папка sut-c-vulnerable має бути сусідньою. Варіанти запускайте по черзі або на різних портах.

## Очікувані вимоги

Основні операції відповідають сусідньому sut-b.
GET /rentals/search?reference=... має шукати лише точний код.
PATCH /rentals/{id} призначений тільки для зміни reference.
Суму визначає Service, статус змінюється тільки через бізнес-дії. Клієнт не повинен підміняти total і status.
Помилки не повинні розкривати структуру БД, SQL чи stack trace.

## Межі комплекту

Ця копія містить production-код, міграції та навмисні вразливості. Готовий regression suite зі звичайного SUT B сюди не копіювався. Наявні залежності або профілі тестового фреймворку не означають наявності тестів. Використовуйте окреме середовище залежностей і власні security-перевірки.

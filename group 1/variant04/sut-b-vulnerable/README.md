# SUT B — Навчальна вразлива версія курсів, варіант 04

Лише локальне security testing з вигаданими даними. Звичайні SUT не змінено.

## Персональне правило

Від 1000 грн — 5%, від 3000 грн — 12%. Застосовується лише більша знижка.

## Запуск

Створіть окрему PostgreSQL БД courses_variant04_security і користувача courses_student, задайте пароль.
Застосуйте міграції за порядком до порожньої БД.
Параметри: SECURITY_DB_HOST (localhost), SECURITY_DB_PORT (55433), SECURITY_DB_NAME (courses_variant04_security),
SECURITY_DB_USER (courses_student), SECURITY_DB_PASSWORD. Файл .env автоматично не читається.
Із папки sut-b-vulnerable:

```sh
mvn spring-boot:run
```

Для Python використовуйте окреме віртуальне середовище.
UI: http://127.0.0.1:8082/index.html. Папка sut-c-vulnerable має бути сусідньою.
Варіанти запускайте по черзі або на різних портах.

## Очікувані вимоги

Основні операції — як у сусідньому sut-b.
GET /enrollments/search?reference=... має шукати лише точний код.
PATCH /enrollments/{id} призначений тільки для зміни reference.
Суму й передоплату визначає Service; статус змінюється через бізнес-дії.
Клієнт не повинен підміняти total, prepaid чи status.
Помилки не повинні розкривати SQL, структуру БД чи stack trace.

## Межі комплекту

Ця копія містить production-код, міграції та навмисні вразливості. Готовий regression suite зі звичайного SUT B сюди не копіювався. Наявні залежності або профілі тестового фреймворку не означають наявності тестів. Використовуйте окреме середовище залежностей і власні security-перевірки.

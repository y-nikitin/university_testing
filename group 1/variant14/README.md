# group 1 — Варіант 14

Мова backend: **Java**. Предметна область SUT B/C: **Навчальні курси**.
Номер варіанта — порядковий номер у підгрупі, а не академічній групі.

| Частина | Призначення |
|---|---|
| [sut-a](sut-a/README.md) | Бізнес-логіка й специфікація для чорної скриньки, unit-тестів, покриття та мутацій |
| [sut-b](sut-b/README.md) | Backend, PostgreSQL, REST API, HTTP-адаптер і regression suite |
| [sut-c-ui](sut-c-ui/README.md) | Готовий UI для браузерних та E2E-тестів |
| [sut-b-vulnerable](sut-b-vulnerable/README.md) | Окрема навмисно вразлива копія backend для security testing |
| [sut-c-vulnerable](sut-c-vulnerable/README.md) | Окремий навмисно вразливий UI для security testing |

SUT A — окрема система зі своїми вимогами. SUT C працює через API SUT B.
Персональні правила наведені в README конкретного SUT. Очікування тестів визначайте за вимогами.
Для лабораторної №1 читайте лише специфікацію SUT A; аналіз коду дозволений із лабораторної №2.

## Звичайний запуск

Підготуйте залежності, окрему PostgreSQL, міграції та параметри DB_* за README SUT B.
Із папки sut-b:

```sh
mvn spring-boot:run
```

UI: http://127.0.0.1:8080/index.html. Якщо порт змінено, використайте його.
Окремий frontend-сервер не потрібний. Збережіть сусідні папки sut-b та sut-c-ui.
Для Java, C# і Go робоча папка запуску — sut-b.

## Security testing

Використовуйте тільки vulnerable-копії з окремою навчальною БД та параметрами SECURITY_DB_*.
Звичайні SUT і їхні БД для цих перевірок не використовуються.
Команди наведено в README sut-b-vulnerable; типовий порт — 8082.
Вразливі застосунки запускайте лише локально з вигаданими даними.
